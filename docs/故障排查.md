# 故障排查

## 1. `apb status` 显示 0 个 agent

```bash
./apb status --server IP:PORT --key "$APB_KEY" --json
```

按顺序检查：

1. 服务端进程是否在监听：`ss -ltnp | grep 30020`。
2. 防火墙 / 安全组是否放行服务端的 `IP:PORT`。
3. agent 端 `APB_SERVER` / `APB_KEY` 是否与 server 一致。
4. agent 日志里的错误：`apb agent` 默认把连接状态和错误打到 stderr。
5. 若服务端返回握手失败或直接断开，通常是 `APB_KEY` 不一致。
6. `apb doctor` 只检查控制器到服务端的一条 Noise 连接，不代表任何 agent 已上线；
   节点是否在线以 `apb status` 为准。

## 2. `apb status` / `apb exec` 报 key 错误

`APB_KEY` 必须是 `apb keygen` 生成的 64 位十六进制字符串，
或 `base64:` 前缀 + 解码后 32 字节的内容。

```text
apb: invalid key: key must be 64 hex characters (or base64:... with 32 bytes)
```

不要用口令、文件名或随便截断的 hex。密钥可以带引号，但不要带换行。
缺少密钥时命令退出码为 `2`。

## 3. agent 名冲突

服务端拒绝同名 agent，日志类似：

```text
server rejected agent: 409 agent `phone-a` is already connected
```

两个手机/ runner 默认名可能相似，请显式指定唯一名称：

```bash
APB_NAME='phone-a' ./apb agent
```

节点名允许字母数字和 `. _ - @ : + ~`，最长 128 字符。

## 4. `exec` 返回 125 / `bad_cwd`

agent 侧不存在或不可进入 `--cwd` 指定的目录。先用 `exec --json -- 'pwd; df -h'` 探测真实路径。

## 5. `exec` 返回 5 / `timed_out:true`

agent 侧已 kill 整个进程组。加大 `--timeout`，或把长任务改为后台并写结果文件：

```bash
./apb exec --name phone -- 'nohup bash -c "sleep 600; echo done > ~/done.txt" >/dev/null 2>&1 & echo started'
```

`--timeout N` 默认 300 秒；`--timeout 0` 表示 agent 侧不主动超时，但控制器仍会在 24 小时后放弃。
如果 stderr 是 `timeout waiting for agent`，说明 agent 没有在 `timeout + 30s` 内返回结果。

## 6. 连接失败退出码 3

- 服务端地址写错、端口没开、防火墙拦截、Noise 握手失败。
- 在服务端本机先用 `apb doctor --json` 验证；再从远端测 `nc -vz IP PORT`。
- 若日志是 `peer did not send APB0 magic`，说明对端不是 apb 协议或连到了错误端口。

## 7. push / pull 返回 6

看 JSON 的 `detail`：

| detail | 原因 |
|---|---|
| `source symlink is not followed by push` | push 的顶层本地路径是符号链接；传目标路径本身 |
| `destination exists: ...` | pull 默认不覆盖已存在的普通文件；改用新目录或先移走旧文件 |
| `remote path not found: ...` | pull 的远端路径写错；远端 `~` 建议用引号包住 |
| `target is a directory: ...` | 目标路径对应的形态不兼容，检查 REMOTE 是否写到了目录名后没加 `/` |
| `sha256 mismatch for ...` | 传输过程中源文件被修改，或链路数据损坏（极少见） |
| `cannot push directory onto existing file: ...` | 源是目录、REMOTE 指向一个已存在普通文件 |
| `timeout waiting for transfer result` | 大目录 / 慢链路超时；确认 agent 在线且磁盘可写 |

提示：

- `push LOCAL` 省略 `REMOTE` 时默认写到 `~/<LOCAL basename>`。
- `pull` 的本地目标始终按目录处理，结果落在 `<本地目录>/<远端 basename>`。

## 8. GitHub Actions agent 连不上

确认仓库 Settings → Secrets and variables → Actions 中已有：

- `APB_SERVER`：形如 `1.2.3.4:30020`
- `APB_KEY`：64 位 hex

然后手动触发 `apb-agent` workflow。看 job 日志中的
`apb agent ... connecting to ...`；如果一直是重连，通常是服务端公网端口不可达，
或服务端 `APB_KEY` 与 secret 不一致。

workflow 输入 `ttl_minutes` 控制 runner 保持连接的最长时间，`name` 可覆盖默认节点名。
如果多个 runner 同时在线，务必指定能区分的 `name`。

## 9. 静态二进制无法在 Termux 运行

确认下载 / 构建的是 aarch64 musl 产物：

```bash
file ./apb
# 期望：ELF 64-bit LSB executable, ARM aarch64, statically linked
chmod +x ./apb
./apb --version
```

Android 上仍需允许 Termux 执行 `$HOME` 下的文件；通常默认可以。
若提示 `Permission denied`，先 `chmod +x ./apb`；若提示架构不匹配，换对应 artifact。

## 10. 找不到命令 / shell 行为不符合预期

agent 默认 shell 选择顺序：

```text
APB_SHELL
→ $PREFIX/bin/bash（Termux）
→ $SHELL
→ /bin/bash
→ /bin/sh
```

- 在 Termux 上建议设置：

  ```bash
  APB_SHELL="$PREFIX/bin/bash" ./apb agent
  ```

- `--raw` 表示不通过 login shell；某些环境变量（如用户级 PATH）可能因此不同。
- `exec` 找不到命令时，先执行 `-- 'echo $PATH; echo $SHELL; command -v xxx'` 确认。
- agent 超时或任务被取消时会 kill 整个进程组；需要让后台任务跨命令继续运行时，用 `setsid` 显式脱离会话/进程组。

## 11. 服务端是否需要配置文件

不需要。`apb serve` 只读 `APB_BIND` / `APB_KEY`，不创建配置、known_hosts 或私钥文件。

## 12. `runApb.sh` 下载二进制失败

一键脚本按 `apb-<target>` 名称从 latest Release 下载：

- `https://github.com/BanYeHanFeng/apb/releases/latest/download/apb-x86_64-unknown-linux-musl`
- `https://github.com/BanYeHanFeng/apb/releases/latest/download/apb-aarch64-unknown-linux-musl`

如果报 404，先确认仓库已经发布正式版；如果只是 GitHub 网络不通，可以设置镜像前缀：

```bash
APB_GH_PROXY='https://gh-proxy.example' \
  bash <(curl -fsSL https://raw.githubusercontent.com/BanYeHanFeng/apb/main/runApb.sh)
```

也可以直接用已有二进制：

```bash
bash runApb.sh --binary /path/to/apb
```

或指定自己托管的下载地址：

```bash
bash runApb.sh --binary-url 'https://example.com/apb-linux-x86_64'
```
