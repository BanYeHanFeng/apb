# APB0 协议（apb 0.2.0）

本文描述 `apb serve` / `apb agent` / `apb exec|push|pull|status|stop` 之间的线上约定。

---

## 1. 传输与握手

```
Client                                         Server
  │── TCP connect ─────────────────────────────►│
  │── b"APB0" ─────────────────────────────────►│
  │── u16(len) + Noise handshake message 1 ────►│
  │◄──────────── u16(len) + handshake message 2 │
  │                                              │
  │  === Noise NNpsk0_25519_ChaChaPoly_BLAKE2s ===
  │── u16(len) + encrypted message ────────────►│
  │◄──────────── u16(len) + encrypted message ──│
```

- 密钥：32 字节；`apb keygen` 输出 64 个 hex 字符，也支持 `base64:` 形式输入。
- 双方只持有预共享密钥；没有 SSH 主机密钥、没有 `known_hosts`。
- 可选读取本地配置文件（`--config FILE` / `APB_CONFIG` / `~/.config/apb/agent.conf`，`KEY=VALUE` 格式，可包含 `APB_KEY`）；不提供配置文件时仍可用命令行参数或 `APB_*` 环境变量运行。
- 每条 TCP 连接对应一个 Noise 会话；应用层单条加密消息上限 65535 字节。
- agent 和 controller 都主动向服务端发起连接，公网只需要暴露服务端一个 TCP 端口。
- 握手 15 秒超时；进入传输态后启用 TCP keepalive（Linux 上 30 秒空闲 + 10 秒间隔探测）。

## 2. 控制帧 `Frame`

每一条加密消息恰好携带一个 Frame。

| tag | Frame | 方向 | 说明 |
|---|---|---|---|
| 1 | `Hello { role, name, version, os, arch, pid }` | 客户端 → 服务端 | `role=1` agent / `role=2` controller |
| 2 | `HelloOk { version }` | 服务端 → 客户端 | 注册成功 |
| 3 | `Error { code, message }` | 双向 | 协议级错误 |
| 4/5 | `Ping` / `Pong` | 双向 | 保活探测 |
| 6 | `RelayReq { target, payload }` | controller → 服务端 | 请求投递到指定 agent |
| 7 | `RelayDeliver { route, payload }` | 服务端 → agent | 服务端分配 route 后投递 |
| 8 | `RelayResult { route, payload }` | agent → 服务端 → controller | 结果回传，服务端按 route 找 controller |
| 9 | `RouteCancel { route }` | 服务端 → agent | controller 断开/取消时取消任务 |
| 10/11 | `ListReq` / `ListRes { peers }` | controller ↔ 服务端 | `apb status` 查询已连接 agent |

- `RelayReq.target` 非空时按名投递；为空且只有一个 agent 在线时自动选择。
- 服务端为每个 `(controller 连接, request_id)` 分配一个 64-bit route。
  push/pull 的后续数据帧继续携带同一个 request id，服务端由此把数据投递到同一 route。
- route 在收到最终 payload（`ExecEnd` / `Error` / `TransferDone` / `Bye`）后清理；
  controller 连接断开时，服务端向对应 agent 发送 `RouteCancel`。

## 3. 数据帧 `Payload`

每个 Payload 的前 9 字节固定为：

```
u8  op
u64 request_id (big-endian)
```

服务端只需要读取这两个字段就能构造错误响应并清理路由，不需要理解命令和文件内容。
字符串和 blob 使用 `u32` 大端长度前缀；整数均为大端；`bool` 占 1 字节。

### 3.1 exec

| op | Payload | 方向 |
|---|---|---|
| 1 | `Exec { id, timeout_secs, cwd, raw, command }` | controller → agent |
| 2 | `ExecOut { id, stream(1=stdout,2=stderr), data }` | agent → controller |
| 3 | `ExecEnd { id, rc, timed_out, reason }` | agent → controller |
| 4 | `Error { id, code, message }` | agent/server → controller |

- agent 用独立线程读取 stdout/stderr，实时发送 `ExecOut`。
- 超时或连接取消时，agent kill 整个进程组。
- `--cwd` 不存在时返回 `Error { code:125 }`。
- 真超时 `rc=124`、`timed_out=true`、`reason="timeout"`；命令自己 `exit 124` 不会被误判。
- `timeout_secs=0` 表示不设置 agent 侧 deadline；真实退出码和信号转换为 `128+signal`。

### 3.2 push / pull 的增量传输

push（controller → agent）和 pull（agent → controller）使用同一套三段式流程。
三段都是**单方向**的，因此批量数据永远不会和反向的回复互相顶死队列：

```
阶段        发送方                        接收方
manifest    Mkdir/Symlink/FileBegin  +   逐个建目录/软链，记录文件清单（rel、size、mode、sha256）
            ManifestEnd           ───►
plans                              ◄───  每个文件给出 FilePlan（skip/whole/delta），
                                        delta 再补 FileSigs（本地副本的块签名）
            ◄── PlanEnd
data        FileStart + Copy/Data  ───►  边收边写临时文件，FileEnd 校验大小与 sha256 后原子 rename
            ... + PushEnd /   ...
            ◄── TransferDone
```

- `seq` 是文件在 manifest 里的序号（只数文件，目录和软链接不占号）。
- 接收方先看自己的本地副本：
  - 内容 sha256 与来源一致 → `action=skip`，该文件**一个数据帧都不传**；
  - 有本地副本且值得做差量 → `action=delta`，附上本地副本的块签名；
  - 没有可复用的副本 → `action=whole`，整文件传输。
- 块签名 20 字节：4 字节滚动校验（rsync 的 a/b 校验和）+ 16 字节 SHA-256 前缀。
  块大小按本地副本大小取 8 KiB / 32 KiB / 128 KiB / 512 KiB 档位，签名单通常小于文件的 0.25%。
- 发送方对源文件做滑动窗口匹配，命中的块发 `Copy { start, len }`（接收方从旧文件里搬），
  其余字节按 16 KiB 一帧发 `Data`。插入、删除、追加、局部改写都只传变化部分。
- `FileEnd.sha256` 是重建后应有的内容哈希（全 0 表示不校验）；接收方校验大小和哈希后才 rename。
- 接收方为了判断“有没有变”需要读一遍自己的本地副本（本地 I/O，不占带宽）；pull 时 agent
  还要先算远端文件哈希，所以会在 `Entry` 之前完整读一遍待传文件。
- pull 会覆盖本地已存在的同名文件（旧实现是直接报错），可以复用本地旧内容的块。

### 3.3 push

| op | Payload | 方向 | 阶段 |
|---|---|---|---|
| 10 | `PushBegin { id, remote_path, source_name, source_is_dir, source_files, source_bytes }` | ctrl → agent | 开始 |
| 11 | `PushReady { id, remote_root }` | agent → ctrl | 开始 |
| 12 | `Mkdir { id, rel, mode }` | ctrl → agent | manifest |
| 16 | `Symlink { id, rel, target, mode }` | ctrl → agent | manifest |
| 13 | `FileBegin { id, seq, rel, size, mode, sha256 }` | ctrl → agent | manifest |
| 19 | `ManifestEnd { id, files }` | ctrl → agent | manifest |
| 22 | `FilePlan { id, seq, action, block_size, block_count }` | agent → ctrl | plans |
| 23 | `FileSigs { id, seq, first, sigs }` | agent → ctrl | plans |
| 26 | `PlanEnd { id }` | agent → ctrl | plans |
| 25 | `FileStart { id, seq }` | ctrl → agent | data |
| 24 | `Copy { id, start, len }` | ctrl → agent | data |
| 14 | `Data { id, data }` | ctrl → agent | data |
| 15 | `FileEnd { id, sha256 }` | ctrl → agent | data |
| 17 | `PushEnd { id }` | ctrl → agent | 结束 |
| 18 | `TransferDone { id, ok, error, remote_path, bytes, sha256 }` | agent → ctrl | 结束 |

- `rel` 为空表示 `PushBegin` 已经解析出的最终路径；目录条目使用相对路径，拒绝绝对路径和 `..`。
- 远端路径解析（rsync 语义）：源是目录时，目标永远是 `<remote_path>/<source_name>`，
  不管 `remote_path` 是否已存在；源是文件时，`remote_path` 已存在目录或以 `/` 结尾才会放进去。
  这样同一条命令每次都落在同一位置，重复 push 才能命中 `skip`/`delta`。
- `action`：`0=whole`、`1=skip`、`2=delta`；`block_size`/`block_count` 只在 delta 时有意义。
- `FileSigs.first` 是这一帧第一个签名对应的块号，一帧最多 819 个签名（16380 字节）。
- 接收方按 `seq` 定位文件：先写同目录隐藏临时文件，`FileEnd` 校验后再原子 `rename`。
- skip 的文件只由接收方 `set_mode` 对齐权限，不产生任何数据帧。

### 3.4 pull

| op | Payload | 方向 | 阶段 |
|---|---|---|---|
| 20 | `PullBegin { id, remote_path }` | ctrl → agent | 开始 |
| 21 | `Entry { id, seq, rel, kind, size, mode, link_target, sha256 }` | agent → ctrl | manifest |
| 19 | `ManifestEnd { id, files }` | agent → ctrl | manifest |
| 22 | `FilePlan { id, seq, action, block_size, block_count }` | ctrl → agent | plans |
| 23 | `FileSigs { id, seq, first, sigs }` | ctrl → agent | plans |
| 26 | `PlanEnd { id }` | ctrl → agent | plans |
| 25 | `FileStart { id, seq }` | agent → ctrl | data |
| 24 | `Copy { id, start, len }` | agent → ctrl | data |
| 14 | `Data { id, data }` | agent → ctrl | data |
| 15 | `FileEnd { id, sha256 }` | agent → ctrl | data |
| 18 | `TransferDone { id, ok, error, remote_path, bytes, sha256 }` | agent → ctrl | 结束 |

- `kind`：`0=dir`、`1=file`、`2=symlink`。
- agent 深度优先遍历目录；controller 写入 `<本地目录>/<远端 basename>/...`。
- 目录可以合并进已存在的目录，软链接会先删除同名文件再重建。
- 普通文件按 3.2 的 skip/delta/whole 处理，已存在的本地文件会被覆盖（临时文件 + 原子 rename）。

### 3.5 生命周期（结束 agent）

| op | Payload | 方向 |
|---|---|---|
| 30 | `Shutdown { id, reason }` | ctrl → agent |
| 31 | `Bye { id, code, reason }` | agent → ctrl |

- `apb stop --name AGENT` 发送 `Shutdown`；agent 回 `Bye`（`code` 是它即将使用的退出码，正常为 0）后结束进程。
- `Bye` 是最终 payload，服务端收到后回收 route。
- agent 先把 `Bye` 写进 socket 并等待写队列排空，再保留约 400 ms 才关闭连接，
  避免 `shutdown(Both)` 的 RST 把刚发出的回复丢掉。
- 结束进程意味着节点不会自动重连：需要有 supervisor（systemd `Restart=always`、`runApb.sh` 的启动流程）才会再次上线。
- `stop` 必须显式指定 `--name` 或 `APB_NAME`，不会在"只有一台节点在线"时自动选中。
- exit：0 已结束、1 被拒（含旧 agent 无法解析该 op）、3 连接/协议错误、5 超时。

## 4. 环境变量与退出码

| 环境变量 | 角色 | 说明 |
|---|---|---|
| `APB_BIND` | server | 监听地址，必须显式包含端口；没有默认端口 |
| `APB_SERVER` | agent/ctrl | 服务端 `IP:PORT`，必须显式包含端口；没有默认端口 |
| `APB_KEY` | 全部 | 64 位 hex 密钥（也支持 `base64:`），可放在配置文件里 |
| `APB_NAME` | agent/ctrl | agent 节点名；控制器为空时表示自动选择 |
| `APB_CONFIG` | agent/ctrl | 可选配置文件路径，默认 `~/.config/apb/agent.conf` |
| `APB_SHELL` | agent | 覆盖远端 shell |
| `APB_TIMEOUT` | ctrl | `exec` 默认超时秒数（默认 300）；`stop` 默认 15 |
| `APB_CWD` | ctrl | `exec` 默认工作目录 |
| `APB_MAX_OUTPUT` | ctrl | JSON 单流保留字节上限，默认 1048576 |

| 退出码 | 含义 |
|---|---|
| 0 | 成功 |
| N | `exec` 普通模式的远端命令 rc（信号为 128+signal） |
| 1 | 本地错误 / 远端执行失败 / 文件传输本地失败 |
| 2 | 缺少或非法 `APB_KEY`、缺少服务端地址 |
| 3 | 连接失败、协议错误或服务端错误 |
| 5 | 超时 |
| 6 | 文件传输失败 |
| 64 | 用法错误 |
| 125 | `exec --cwd` 目录不存在 |

配置优先级：命令行参数 > `APB_*` 环境变量 > 配置文件的 `APB_*` 值。

`push` / `pull --json` 的统计字段：

| 字段 | 含义 |
|---|---|
| `bytes` | 真正上线传输的文件内容字节（差异部分 + 新增文件） |
| `total_bytes` | manifest 里所有文件的总大小 |
| `reused_bytes` | 没有上线的字节：命中的旧块 + 内容完全相同的文件 |
| `files` | 文件总数 |
| `skipped_files` | 内容与对端完全一致、零传输的文件数 |
