# 安全模型

## 资产

| 资产 | 位置 | 保护 |
|---|---|---|
| 预共享密钥 `APB_KEY` | 服务端 / agent / controller 的环境变量或 GitHub Actions secret | 不写入配置文件、不提交仓库；优先通过环境变量传递 |
| 节点控制权 | 持有 `APB_KEY` 即可连接服务端并控制对应 agent | 泄露等价于节点被接管 |
| 用户命令 | 只在 agent 本机 shell 执行 | 服务端只转发，不解析、不执行 |
| 传输内容 | TCP + Noise 加密 | 被动监听者无法读取或伪造 |
| 写入的远端文件 | `push` 显式指定的路径 | 临时文件 + SHA-256 校验 + 原子 `rename` |

## 信任边界

- **服务端**：负责认证、注册、按名路由；不执行用户命令，不持久化节点配置。
  但服务端是 Noise 终止点，能看到转发中的全部明文 payload。
- **agent**：以启动用户的权限执行命令；`exec` 的权限就是 agent 进程的权限。
- **controller**：通过服务端发送 payload；同一把密钥下的 agent 与 controller 互信。
- **公网**：只需要暴露服务端一个 TCP 端口；agent 和 controller 都是出站连接。

## 已实施的加固

- Noise `NNpsk0_25519_ChaChaPoly_BLAKE2s` 预共享密钥握手；没有 PSK 无法完成握手。
- 应用层使用显式长度前缀消息，单条消息上限 65535 字节；协议头使用固定布局，不反序列化任意对象。
- 握手 15 秒超时；进入传输态后启用 TCP keepalive。
- push 的每个文件都校验声明的 SHA-256 后才原子落盘。
- push/pull 的相对路径拒绝绝对路径和 `..`，防止目录穿越。
- agent 超时、controller 断开或服务端取消任务时，终止整个子进程组。
- agent 断线指数退避重连（1–30 秒），避免断网时的重连风暴。
- `runApb.sh` 一键脚本从 `/dev/tty` 无回显读取 `APB_KEY`，只通过环境变量传给 agent 进程，
  不写入配置文件，也不把密钥放进 agent 的命令行参数。
- GitHub Actions 路径只从 secrets 读取 `APB_SERVER` / `APB_KEY`，不写入 workflow inputs。

## 风险与建议

- 同一把密钥同时给 agent 和 controller 使用；应按环境规划独立密钥，并在泄露时全部更换。
- 服务端一旦被攻破，攻击者可以读取转发的明文 payload（服务端位于 Noise 终止点）。
  对高敏感场景，应将服务端部署在自己控制的基础设施上。
- agent 是远程执行入口，应以最小权限用户运行；不要在手机 / runner 上以不必要的最高权限常驻。
- `APB_KEY` 一旦进入 shell history、日志、进程列表或被读取，应视为泄露并轮换。
  `--key` 会出现在进程参数中；能使用环境变量时不要用命令行传密钥。
- 控制器的 `exec` 命令、`push` 源文件和 `pull` 目标都会进入本机 shell 历史或 CI 日志；
  不要把长期凭证直接写进命令参数，需要 secret 时使用目标环境的密钥管理。
- 不要把 `APB_KEY` 与不可信进程共享环境；agent 会继承执行命令的环境变量。
