# 构建与测试

本文汇总 `apb` 的本地构建、静态 musl 交叉编译、构建工作流、测试与发布方式。
运行方式、命令契约和 GitHub Actions 临时节点见 [使用手册.md](使用手册.md)。

---

## 准备二进制

本机可跑 Rust 工具链时，直接原生构建即可：

```bash
cargo build --release --locked
# 产物：target/release/apb
```

在临时 VPS / CI / 构建容器里可交叉编译静态 musl 单文件（推荐用于 Termux 和 runner）：

```bash
rustup default stable
rustup target add x86_64-unknown-linux-musl aarch64-unknown-linux-musl
cargo install cargo-zigbuild --locked
python3 -m pip install --user ziglang

# x86_64 Linux / GitHub Actions runner
cargo zigbuild --release --locked --target x86_64-unknown-linux-musl

# aarch64 Android / Termux
cargo zigbuild --release --locked --target aarch64-unknown-linux-musl
```

产物：

- `target/x86_64-unknown-linux-musl/release/apb`
- `target/aarch64-unknown-linux-musl/release/apb`

## 构建与发布

`.github/workflows/ci.yml`（名称：`构建与发布`）把构建校验与发布合并为一个工作流：

- push `main` / PR / 手动触发（不填 tag）：运行 `测试（本机）` 和 `静态构建 <target>`；
- push `main` 且提交标题严格为 `发布: vxxx`（例如 `发布: v0.1.1`）：自动创建 tag（`v0.1.1`），构建并发布为 latest 正式版；
- push `v*` tag：由 tag 触发，测试和构建通过后发布为 latest 正式版；
- 手动触发 `workflow_dispatch` 并填写 tag：发布对应标签；不填 tag 则只构建。

`静态构建 <target>` 任务用 Zig 交叉编译 `x86_64-unknown-linux-musl` 和 `aarch64-unknown-linux-musl`，
上传静态单文件；发布任务直接复用这些产物，不再重复构建。GitHub 会记录构建产物与 Release 资产的
SHA-256 摘要，无需另外生成 / 上传 `.sha256` 文件。

## 开发与测试

```bash
cargo fmt --check
cargo test --locked --all-targets
```

`tests/e2e.rs` 会在 loopback 上拉起 `apb serve`、`apb agent`，验证 `exec`、`push`、`pull` 全链路，
不依赖 sshd、外部网络或配置文件。
