# 使用手册

本文覆盖 `apb` 的架构、三种角色的启动方式、命令与文件传输契约，以及 GitHub Actions 临时节点。
构建/测试见 [构建与测试.md](构建与测试.md)，线协议见 [协议.md](协议.md)，排障见 [故障排查.md](故障排查.md)。

---

## 设计承诺

- 客户端只是一个静态单文件 `apb`：不装 sshd、不装 openssh、不装运行时依赖。
- 只需要 **服务端 IP + 端口 + 32 字节密钥**；agent 和控制器都主动出站。
- 配置只读环境变量或命令行参数：`APB_SERVER`、`APB_BIND`、`APB_KEY`、`APB_NAME` 等。
- 没有配置文件、known_hosts、持久私钥文件；`agent` / `serve` 自身不写用户目录。
- 服务端只做认证、注册和按名路由，不替任何节点执行命令。
- 临时 CI 节点直接从 GitHub Actions secrets 读取地址和密钥，公开仓库也能用；
  公开仓库的托管 runner 规格通常优于私有仓库，且 runner 跑完即焚。

---

## 架构

```
Termux / Android / CI runner / Linux        公网 Linux（自控服务器）
┌────────────────────────────┐   TCP+Noise  ┌────────────────────────────────┐
│  apb agent                 │ ───────────► │  apb serve                     │
│  APB_SERVER=IP:PORT        │   主动出站    │  APB_BIND=0.0.0.0:30020        │
│  APB_KEY=<64 hex>          │              │  APB_KEY=<64 hex>              │
│  无 sshd / 无配置文件        │              │  只认证、注册、按名路由          │
└────────────────────────────┘              └───────────────▲────────────────┘
                                                            │ TCP+Noise
                                              ┌─────────────┴──────────────┐
                                              │  apb status / exec / push  │
                                              │  apb pull / doctor         │
                                              │  本机 / AI 运行端（控制器） │
                                              └────────────────────────────┘
```

- `apb serve`：公网入口，仅负责认证、注册、按名路由。
- `apb agent`：运行在被控节点，断线指数退避重连（1–30 秒）。
- `apb status/exec/push/pull/doctor`：控制器，直接连接服务端，经服务端转发到指定 agent。
- `apb keygen`：生成 32 字节密钥（64 个 hex 字符）。

## 快速开始

> 以下步骤假设已经取得 `apb` 二进制；构建方法见 [构建与测试.md](构建与测试.md)。

### 1) 服务端

```bash
# 生成并保存密钥（只显示一次；也可以直接作为 Actions secrets 使用）
export APB_KEY="$(./apb keygen)"
echo "$APB_KEY"          # 不要写进仓库

./apb serve \
  --bind 0.0.0.0:30020 \
  --key "$APB_KEY"
```

`APB_BIND` / `APB_KEY` 也可以用环境变量提供，例如：

```bash
APB_BIND=0.0.0.0:30020 APB_KEY="$APB_KEY" ./apb serve
```

服务端不会创建配置文件，只往 stdout/stderr 打日志。

### 2) Agent：手机 / Termux / GitHub Actions runner / Linux 节点

把对应架构的静态二进制 `apb` 放进目标环境后：

```bash
chmod +x ~/apb
APB_SERVER='1.2.3.4:30020' \
APB_KEY='<64位hex>' \
APB_NAME='my-node' \
~/apb agent
```

- 只依赖服务端地址、密钥和可选节点名，不需要 `pkg install openssh`。
- `APB_SERVER`、`APB_KEY`、`APB_NAME` 均可替换为 `--server` / `--key` / `--name`。
- 未设置 `APB_NAME` 时默认是 `USER@HOSTNAME`，服务端会拒绝同名 agent；
  手机、runner 之间容易重名，建议显式指定 `APB_NAME`。
- 想后台常驻可自行用 `nohup`、`setsid`、Termux 的 termux-services 等；
  agent 自身只负责维护一条出站 TCP，断线后自动重连。
- 同一个密钥可以连接多个 agent；服务端按 `APB_NAME` 区分。

### 3) 从本机控制

```bash
./apb status --server 127.0.0.1:30020 --key "$APB_KEY" --json

./apb exec \
  --server 127.0.0.1:30020 --key "$APB_KEY" \
  --name my-node --json -- \
  'uname -a; pwd; echo hello'

./apb push --server 127.0.0.1:30020 --key "$APB_KEY" \
  --name my-node ./file.bin '~/file.bin'

./apb pull --server 127.0.0.1:30020 --key "$APB_KEY" \
  --name my-node '~/logs/app.log' ./logs/

./apb doctor --server 127.0.0.1:30020 --key "$APB_KEY" --json
```

当服务端上只有一个 agent 在线时可以省略 `--name`；多个 agent 时必须指定节点名。

## `exec` 契约

```bash
apb exec [--server A] [--key K] [--name AGENT] [--json] [--b64] [--raw] \
  [--timeout SECONDS] [--cwd DIR] [--max-output BYTES] -- COMMAND...
```

- `--` 之后的位置参数按顺序用空格拼接成一条命令，交给 agent 的 shell 执行。
  命令里有重定向、管道、分号时，建议整体加引号。
- 普通模式 stdout/stderr 实时透传，退出码等于远端命令 rc。
- `--json` 返回单行 JSON，`ok:true` 只代表命令执行完成；命令失败看 `rc`。

```json
{
  "ok": true,
  "rc": 0,
  "duration_ms": 59,
  "timeout_s": 300,
  "cwd": "",
  "command": "echo hi",
  "stdout": "hi\n",
  "stderr": "",
  "stdout_bytes": 3,
  "stderr_bytes": 0,
  "stdout_truncated": 0,
  "stderr_truncated": 0,
  "timed_out": false,
  "ended_reason": "ok"
}
```

- `--b64`（配合 `--json`）返回 `stdout_b64` / `stderr_b64`，适合二进制输出。
- `--timeout N`：agent 侧超时秒数，默认 300，可用 `APB_TIMEOUT` 覆盖。
  真超时返回 `timed_out:true`、`ended_reason:"timeout"`，退出码 `5`。
  `--timeout 0` 表示 agent 侧不主动超时；控制器仍受 24 小时上限保护。
- `--cwd DIR`：agent 侧解析 `~` 作为工作目录；目录不存在返回 `bad_cwd`，退出码 `125`，不会静默回退。
- `--raw`：不通过 login shell 执行；默认会按 shell 类型使用 `-lc`。
- `--max-output N`：限制 JSON 中每个流保留的字节数，默认 1048576，可用 `APB_MAX_OUTPUT` 覆盖；
  超出部分只通过 `stdout_truncated` / `stderr_truncated` 标记，远端命令仍会被完整读取到结束。
- 远端 shell 选择顺序：`APB_SHELL` → Termux `$PREFIX/bin/bash` → `$SHELL` → `/bin/bash` → `/bin/sh`。
- agent 侧超时 / controller 断开 / `RouteCancel` 触发时，会 kill 当前命令的整个进程组。

## 文件传输契约

- 所有路径都以长度前缀传输，不经过本机 shell 展开；`~` / `~/...` 由 agent 侧解析。
- 目录内的相对条目拒绝绝对路径和 `..`，防止目录穿越；`REMOTE` 本身可以是绝对路径。

### push

```bash
apb push [--server A] [--key K] [--name AGENT] [--json] LOCAL [REMOTE]
```

- `LOCAL` 可以是文件或目录；顶层符号链接不会跟随，目录内部的符号链接会原样传输。
- `REMOTE` 省略时默认 `~/<LOCAL basename>`。
- 若 `REMOTE` 是已存在目录，或以 `/` 结尾，则最终落点会追加 `LOCAL` 的 basename；
  否则 `REMOTE` 作为精确目标路径。
- 文件推送到已存在的目录是允许的（自动进入该目录）；把目录推送到已存在的普通文件会报错。
- 每个文件先写同目录隐藏临时文件，校验大小和 SHA-256 后再原子 `rename`；
  文件权限保留，不会保留 UID/GID。
- JSON 成功输出：

```json
{"ok":true,"direction":"push","source":"./file.bin","remote_path":"/root/file.bin","method":"apb2","bytes":1024,"sha256":null,"verified":true,"backup_path":null,"duration_ms":37}
```

### pull

```bash
apb pull [--server A] [--key K] [--name AGENT] [--json] REMOTE [LOCAL_DIR]
```

- `LOCAL_DIR` 始终按目录处理，省略时默认当前目录 `.`。
- 远端是文件时，落点是 `<LOCAL_DIR>/<远端 basename>`；
  远端是目录时，落点是 `<LOCAL_DIR>/<远端 basename>/...`，目录结构原样保留。
- 支持普通文件、目录和符号链接；默认拒绝覆盖已存在的普通文件。
- JSON 成功输出：

```json
{"ok":true,"direction":"pull","source":"/root/file.bin","local_path":"./file.bin","remote_path":"/root/file.bin","method":"apb2","bytes":1024,"sha256":null,"duration_ms":29}
```

> `sha256` 字段当前为占位符；pull 不做全文件摘要校验，push 会在 agent 侧逐文件校验 SHA-256。

## GitHub Actions 临时节点

仓库提供两个工作流：

1. `.github/workflows/apb-agent.yml`（名称：`apb 临时节点`）
   - 手动触发 `workflow_dispatch` 启动一个 GitHub 托管 runner；
   - runner 从 `secrets.APB_SERVER` / `secrets.APB_KEY` 读取配置；
   - 可选输入：`ttl_minutes`（连接保持时间，默认 120）和 `name`（节点名覆盖）；
   - 默认节点名为 `<owner>-gh-<run_id>`，不执行用户命令前不会在 runner 上留下配置；
   - 任务超时或手动取消后，runner 本身即销毁。

2. `.github/workflows/ci.yml`（名称：`构建与发布`）
   - push `main` / PR / 手动触发（不填 tag）时，`测试（本机）` 运行
     `cargo test --locked --all-targets`，`静态构建 <target>` 用 Zig 交叉编译
     `x86_64-unknown-linux-musl` 和 `aarch64-unknown-linux-musl`，上传静态单文件；
   - 推送到 `main` 且提交标题为 `Vxxx正式版`（例如 `V0.1.1正式版`）、推送 `v*` tag，
     或手动触发并填写 tag 时，复用构建产物发布为 latest 正式版；
   - 提交标题匹配时创建的 tag 为小写 `v0.1.1`；手动触发不填 tag 则只构建不发布。

在公开仓库使用 agent 工作流前，只需在仓库 Settings → Secrets and variables → Actions 里加入：

| Secret | 值 |
|---|---|
| `APB_SERVER` | 你的公网 `IP:PORT` |
| `APB_KEY` | `apb keygen` 生成的 64 位 hex 密钥 |

然后手动触发 `apb-agent` 工作流，该 runner 就会出现在 `apb status` 中。
